## Changes

- Discover managed patch sites from code structure instead of enforcing a fixed game DLL hash. Backend initialization, ENet connection, and avatar-copy targets must be unique and pass exact signature and IL checks. Compatible updates can retain support despite changed metadata tokens, coroutine indices, or target method names. Incompatible or ambiguous structures stop installation; backend activation waits until all patches are installed, with rollback on failure.
- Wait for both the Mono root domain and managed main thread object before attaching the bridge worker. This addresses the early-attachment startup race observed with a game crash inside Mono. Record startup-state transitions and retain process exit codes in decimal and hexadecimal when initialization fails.
- Retry transient module snapshot errors 24 and 299 during injection-time enumeration for up to ten seconds, preserving the complete original errors and diagnostic history. Access denial and other errors still fail immediately. Only module enumeration is retried, never the remote DLL-loading operation. Keep assembly fingerprints for diagnostics and reject file changes during the same startup.
- Make `README.md` English by default and provide `README.zh-CN.md` for simplified Chinese. Keep `PRODUCT.md` and `AGENTS.md` in English, document English comments/documentation as the default, and retain supported runtime translations and bilingual release warnings.
- Release ZIPs retain all five runtime files, both READMEs, and the Harmony license. Repository-only `PRODUCT.md` and `AGENTS.md` are excluded; README design-document links point to the repository. The release workflow reads warnings from the renamed READMEs.

## Validation

Automated release-candidate verification passed using the configured local Windows x64 MSVC toolchain: `cargo fmt --all -- --check`, `cargo test --workspace --locked`, `cargo xtask test-managed`, `cargo xtask package`, and `powershell.exe -NoProfile -NonInteractive -File tools/tests/LauncherFailureTests.ps1`. Coverage includes Mono readiness timing, structural discovery and rejection, exact constructor signatures, patch activation/rollback, module snapshot retries and raw-error preservation, process exit codes, localized UI, ENet channels, avatar pixel copies, and memory IPC. Packaging checks the complete archive allowlist, hashes, and executable manifest. These automated checks do not launch or inject into the game.

Separate authorized manual testing of the implementation before the version bump used two locally launched instances, one Steam account, and `127.0.0.1`, with a temporary isolated harness rather than a shipped dual-instance mode. The updated game assembly fingerprint was `c16c02d74985fafdf5c02ab0c5d33ca5c5cf646be4b064474f8f40989e4ff13c`. Both instances reached LAN readiness. Hosting, joining, character assignment, battle-goal selection, readiness, battlefield loading, and first-round ability selection/initiative synchronization passed. Both backends reported running; local and remote avatars were 184×184 with one mip and matching PNG hashes. Client exit produced the expected host disconnect notification. Both test instances were closed afterward. Production existing-instance rejection remains unchanged.

## Limitations

Structural checks do not prove compatibility with every future update or network protocol. Backend type names, network properties, UI interfaces, and guarded IL patterns must remain compatible. Manual testing did not cover different accounts or computers, firewall/NAT behavior, mixed game versions, a complete combat round, long-running sessions, administrator-mode Steam overlay behavior, or repeated cold-start stress. The Mono startup change passed limited local launches; this does not establish that every cold-start failure is resolved. Steam identity initialization is still required and fully offline startup is unsupported.

## 更新内容

- 不再通过固定游戏 DLL 哈希白名单限制版本，改为按代码结构寻找托管补丁位置。后端初始化、ENet 连接和头像复制入口必须唯一，并通过精确签名与 IL 校验。保留这些结构的更新可适应元数据 token、协程编号或目标方法名称变化；结构不兼容或有歧义时停止安装，所有补丁安装完成后才激活 LAN，失败时尝试回滚。
- 原生桥接在附加工作线程前，同时等待 Mono 根域和托管主线程对象出现，针对已观察到的 Mono 内部崩溃启动竞争条件进行修复。记录运行时状态变化，初始化失败时保留十进制与十六进制进程退出码。
- 注入阶段读取模块快照遇到 Windows 错误 24 或 299 时，最多重试十秒，保留完整原始错误和诊断历史；拒绝访问及其他错误仍立即失败。只重试模块枚举，不重复执行远程 DLL 加载。程序集哈希继续用于诊断，并拒绝同一次启动期间文件发生变化。
- 默认 `README.md` 改为英文，简体中文说明改为 `README.zh-CN.md`。`PRODUCT.md` 和 `AGENTS.md` 使用英文，并规定代码注释和文档默认使用英文；保留运行时翻译及双语发布警告。
- Release ZIP 保留五个运行文件、双语 README 和 Harmony 许可证，不再包含仅供仓库使用的 `PRODUCT.md` 或 `AGENTS.md`。README 的设计文档链接指向仓库；发布工作流从新的 README 文件名提取双语警告。

## 验证

自动发布候选验证已通过：沿用本地 Windows x64 MSVC 工具链，执行格式检查、工作区 Rust 测试、托管回归测试、完整打包及 `LauncherFailureTests.ps1`。覆盖 Mono 就绪时序、结构探测与拒绝路径、精确构造签名、补丁激活及回滚、模块快照重试与原始错误保留、进程退出码、多语言 UI、ENet 通道、头像像素复制及内存 IPC。打包检查完整文件白名单、内容哈希和 EXE 清单。自动验证不会启动或注入游戏。

版本升级前，另经用户授权对相同实现进行了本机双实例实测：使用同一 Steam 账号及 `127.0.0.1`，通过隔离的临时测试程序启动，不随正式工具提供双开模式。更新后游戏程序集指纹为 `c16c02d74985fafdf5c02ab0c5d33ca5c5cf646be4b064474f8f40989e4ff13c`。两端均完成 LAN 初始化，开房、加入、角色分配、战斗目标选择、准备状态、战场载入及第一回合选牌和先攻同步通过。两端后端均处于运行状态，本地及远端头像均为 184×184、单 mip，PNG 哈希一致。客户端退出后房主正确显示断线提示，两个测试实例均已关闭。正式启动器继续拒绝接管已有游戏实例。

## 限制

结构校验不能保证所有未来更新或网络协议均兼容；后端类型名、网络属性、界面接口及受保护的 IL 特征仍需兼容。本次未验证不同账号或电脑、防火墙/NAT、混合游戏版本、完整战斗回合、长时间会话、管理员模式 Steam 叠加界面或反复冷启动压力场景。Mono 启动修复通过了有限次数的本机启动，不能据此认定所有冷启动故障均已解决。仍需 Steam 身份初始化，不支持完全离线启动。
